# Debugging: resume-partial-results

Status: [OPEN]

## Симптом

Проверка считает все targets обработанными по наличию корректного JSON с полем `results`, хотя часть запусков ранее завершалась ошибками или блокировкой.

## Гипотезы

1. В JSON сохранился частичный результат после остановки процесса.
2. Домен есть в `blocked`, но JSON ошибочно считается завершенным.
3. Повторный запуск перезаписал частичный JSON и скрыл исходный статус.
4. История запусков в `filter_audit.jsonl` не учитывается проверкой.
5. Для resume требуется явный успешный статус запуска, а не только валидная структура JSON.

## План

- Сопоставить 542 targets с JSON результатами.
- Проверить blocked-файлы и причины остановки.
- Проверить audit-журнал по каждому target.
- Определить надежный критерий завершения.

## Полученные данные

- В `targets.txt` найдено 542 уникальных targets.
- В `results` есть 542 JSON-файла `*.get.json`, но в `blocked` есть 227 соответствующих файлов.
- Для таких targets JSON и `blocked` могут иметь одинаковое время изменения: JSON является частичным результатом остановленного запуска.
- В `filter_audit.jsonl` присутствуют события `run_start`, а также события автоматических фильтров и рестартов.
- При проверке с учетом `blocked` завершенными остаются 316 targets, 226 targets должны быть обработаны повторно.

## Вывод

Проверка только `results/*.json` была недостаточной. Частичный JSON после блокировки не является успешным завершенным результатом. Критерий изменен: если `blocked/<name>.json` существует и создан не раньше результата, target снова попадает в очередь. Если после блокировки результат был успешно перезаписан позже, target считается завершенным.
